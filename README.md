## 2차: 이미지 불법광고 탐지 (2026-11)

1차 도구는 이미지 안의 광고를 보지 못한다. 2차는 「글자를 읽어서(OCR)」「그림을 보고」「둘 다 보고」 판정하는 모델을 같은 실제 이미지 평가셋에서 비교했다.

**동결.** 코드·모델·문턱·M3 구간은 커밋 `4ef0728` 로 동결했다. 평가셋 3,000장은 평가 담당(준아)만 가졌고, 2026-11-16 이 커밋으로 추론해 라벨 v1.2 로 한 번만 채점했다. 이후 커밋은 동결 모델을 바꾸지 않는다(`f07fda4` 는 검증셋 Grad-CAM 점검만 더했다).

**평가셋 결과.** 채점 2,910장(불법 84장, 출처 그룹 14개, unsure 90장 제외). 숫자의 정본은 준아의 팀 보고서다.

| 모델 | 보는 것 | 정밀도 | 재현율 | F1 | PR-AUC |
|---|---|---|---|---|---|
| M3 | M2 점수가 [0.05, 0.8) 인 이미지만 Claude Opus 5.5 비전에 다시 묻기 | 0.940 | 0.940 | 0.940 | 0.950 |
| M2 (다영) | 그림(CLIP) + OCR 글(KLUE 임베딩) | 0.921 | 0.833 | 0.875 | 0.937 |
| B1+ TF-IDF | OCR 글 | 0.851 | 0.750 | 0.797 | 0.828 |
| B1+ KLUE | OCR 글 | 0.870 | 0.714 | 0.784 | 0.818 |
| B1 | OCR 글 + 1차 문장 분류기 v9n | 0.772 | 0.726 | 0.748 | 0.788 |

M3 는 평가셋 3,000장 중 60장을 물었고 비용은 0.74달러였다. 출처 그룹 단위 부트스트랩 95% 구간이 0을 넘는 비교는 M3 > M2 와 M2 > TF-IDF(PR-AUC)다.

| 위치 | 내용 |
|---|---|
| `image_collect/` | 이미지 수집기(Playwright)·OCR·라벨 초안 도구, 수집 진행보고서(`진행보고서.md`) |
| `image_spec/` | 넘겨주기 H1\~H7 파일 형식 명세(11-03 초안, 실제로 바뀐 값은 문서 첫머리) |
| `image_models/` | B1·B1+·M3 코드, 평가셋 추론 노트북, M2 Grad-CAM 점검. 실행법은 `image_models/README.md` |

레포에 없는 것: 이미지·라벨·OCR 데이터, 실행 결과(`image_models/runs*/`), M2 학습 코드와 가중치(다영이 따로 전달), 평가셋과 채점 기록(준아 PC).

## 1차: 텍스트 탐지 도구 (공모전, 2026-10)

접수 마감 2026-10-23(금) 18시. 점검할 웹사이트 URL 하나를 넣으면 하위 페이지·게시글·댓글·iframe 안에 게시되거나 숨겨진 불법광고를 찾아, 유형과 위치를 화면과 `result.json` 으로 알려 주는 Windows 11 도구다.

### 최종판 (v9n + API v2x, 2026-10-21)

사이트 주소 하나를 받아 최대 2,000쪽 또는 20분 동안 실제 브라우저(Edge)로 돌아다니며 숨기거나 위장한 불법광고를 찾아
`result.json`(4종)과 `result_extra.json`(추가 유형)을 쓴다. 규칙과 학습 판정기로 후보를 고르고, 애매한 것만 Claude API(claude-haiku-5-5)에 2차로 묻는다.
키가 없으면 API 없이 끝까지 돈다. 이전 시험판(`A_crawler`·`B_detector`·`D_ui_docs`)은 이 판으로 바꾸며 지웠다(git 이력에 남아 있음).

- 성능·한계·요강 해석: `인계문서_보고서팀.md`
- 빌드: `빌드방법.txt` (Windows, Python 3.12.7, `package/requirements.txt`)
- 사용법: `package/사용설명서.txt`
- 결과 형식 점검: `python model2/요강점검.py <결과 폴더>`
- 실행 파일은 레포에 올리지 않는다(약 300 MB). 제출 zip 으로 따로 전달한다.

### 폴더

| 위치 | 내용 |
|---|---|
| `model/`, `model2/` | 탐지 코드. 진입점은 `model2/scan4.py`(크롤러·판정) |
| `package/detect.py` | 실행 파일 진입점, `package/build.py` 로 빌드 |
| `package/model_v9n/` | 학습된 판정 모델 |
| `model2/채점.py`, `score_key.py`, `score_extra.py` | 사이트 채점(정답 파일과 비교, 집계만 출력) |
| `model2/score_test_etc.py` | 봉인 시험셋 추가 유형 채점(집계만 출력) |
| `C_data/` | 실측 샘플(DECOY · ETC · 난독화 조합 · JAMO · OFFSCREEN), 키워드 사전, 요강 스키마 정답셋, 모의 사이트, 채점기 |

### 요강에서 정한 탐지 유형

적격평가는 아래 4종만 본다. 그 밖의 유형은 `technique: "ETC"` 와 `extra_finding` 으로 `result_extra.json` 에 따로 적는다.

| 코드 | 유형 | 예 |
|---|---|---|
| `HOMOGLYPH` | 닮은꼴 글자 위장 | 키릴·전각 문자, 숫자를 섞음 |
| `JAMO` | 자모 분해 | 음절을 자모로 쪼갬 |
| `TRANSPARENT` | 투명 텍스트 | 배경과 같은 색, `opacity:0`, `color:transparent` |
| `OFFSCREEN` | 화면 밖 은닉 | `font-size:0~1px`, `left:-9999px`, `display:none` |

## 저장소 규칙

- `.env`(API 키)와 `**/data/raw/`(수집 원문)는 올리지 않는다.
- 결과 발표 전까지 비공개로 둔다(요강: 접수 이후 공개된 아이디어는 보호받지 못한다).
