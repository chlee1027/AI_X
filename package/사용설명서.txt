공공 웹사이트 불법광고 탐지 도구 (AdDetector) 사용설명서
판: v9n (2026-10-21), API 없음 / API 판 두 가지

[결과 파일 위치] 기본은 AdDetector.exe 가 있는 폴더입니다.
  - result.json       : 적격평가용 결과(주요 4종)
  - result_extra.json : 추가 유형 탐지 결과(technique "ETC", extra_finding 에 유형 이름)
  --out 으로 다른 폴더를 주면 두 파일 모두 그 폴더에 생깁니다.
[API 판 키] 실행 파일 옆 .env 파일의 ANTHROPIC_API_KEY (자세한 것은 9절)

1. 무엇을 하는 도구인가
  사이트 주소(URL) 하나를 넣으면 그 사이트의 하위 쪽과 iframe 을 실제 브라우저로 열어 보며,
  숨기거나 위장한 불법광고 글자를 찾습니다. 찾는 기법은 네 가지입니다.
    - 닮은꼴 글자 (HOMOGLYPH)  : 한글·영문을 모양이 비슷한 다른 문자로 바꿔 쓴 것
    - 자모 분해   (JAMO)       : 글자를 자음·모음으로 풀어 쓴 것 (예: ㅂㅏㅋㅏㄹㅏ)
    - 투명 글자   (TRANSPARENT): 글자색·투명도로 보이지 않게 한 것
    - 화면 밖 숨김 (OFFSCREEN)  : 화면 밖 위치·크기 0·display:none 등으로 숨긴 것
  이 밖에 추가 유형 열한 가지를 따로 찾아 result_extra.json 에 적습니다(5절).
  결과는 result.json(제출 형식), result_extra.json(추가 유형), report.html(결과 확인 화면)로 저장됩니다.

2. 필요한 환경
  - Windows 11 (또는 Windows 10), GPU 필요 없음
  - Microsoft Edge (Windows 에 기본으로 설치되어 있음)
  - 파이썬 등 다른 프로그램 설치는 필요 없습니다.
  - 검사할 사이트에 접속할 수 있는 네트워크

3. 설치
  - 받은 압축 파일을 원하는 곳에 풉니다. 압축 파일 안에서 바로 실행하지 마세요.
  - 풀린 AdDetector_API 폴더(API 없는 판은 AdDetector 폴더) 안의 파일·폴더를 옮기거나 지우지 마세요.
      AdDetector.exe   실행 파일
      _internal\       실행에 필요한 라이브러리 (필수)
      model_v9n\        판정 모델 (필수)
      settings.json    API 사용 여부 설정
      .env.example     API 키 설정 예시 (API 판에서 .env 로 바꿔 씀)
  - 처음 실행할 때 Windows 보안 경고(SmartScreen)나 백신 경고가 뜰 수 있습니다.
    「추가 정보」 -> 「실행」을 누르면 됩니다. (서명되지 않은 실행 파일이라 뜨는 일반 경고입니다)

4. 실행 방법
  [방법 1] 더블클릭
    1) AdDetector.exe 를 더블클릭합니다.
    2) 「검사할 사이트 주소(URL)를 입력하세요」가 나오면 주소를 붙여 넣고 엔터를 누릅니다.
    3) 「[탐지 시작]」이 표시되고, 끝나면 「[탐지 완료]」와 검출 개수가 표시됩니다.
    4) 결과 확인 화면이 브라우저에서 자동으로 열립니다. 창은 엔터를 누르면 닫힙니다.

  [방법 2] 명령 창 (PowerShell 또는 명령 프롬프트)
    cd "AdDetector 폴더 경로"
    .\AdDetector.exe https://검사할.사이트.주소/

    선택 사항:
      --out "폴더"        결과를 다른 폴더에 저장 (기본: AdDetector 폴더)
      --minutes 20        최대 검사 시간(분). 이 시간이 되면 멈추고 그때까지의 결과를 저장
      --max-pages 2000    최대 검사 쪽수
      --delay 0.2         쪽 사이 대기 시간(초). 사이트 부담을 줄이려면 늘립니다
      --no-open           끝난 뒤 결과 화면을 자동으로 열지 않음

5. 결과 파일
  - result.json : 제출 형식의 결과. 검출 1건마다 쪽 주소(url), 위치(location, CSS 선택자),
                  근거 원문(evidence_text), 기법(technique)이 들어 있습니다.
                  iframe 안 검출은 location 이 iframe[src="..."] >>> 선택자 꼴입니다.
  - result_extra.json : 추가 유형 탐지 결과. 구조는 result.json 과 같고 technique 은 "ETC",
                  유형 이름은 extra_finding 에 들어 있습니다.
      ZERO_WIDTH    보이지 않는 글자(소프트 하이픈·폭 없는 공백)를 광고 문구 글자 사이에 끼운 것
      ENCODING      광고 문구를 링크 주소의 퍼센트 인코딩(%EC%A3..)이나 HTML 문자 참조(&#53076;)로만 적은 것
      META_CLOAKING 화면에는 없고 head 의 메타 태그(description·og·twitter)·title 에만 광고 문구를 둔 것
      CSS_CONTENT   광고 문구를 스타일시트의 ::before·::after content 값에만 둔 것
      LINK_CLOAKING 링크 글은 평범한데 주소가 단축 주소·의심 도메인(.top 등)·무작위 꼴 호스트로 가는 것
    아래 여섯은 광고로 판정된 글의 글자 변형 방식입니다.
      SYMBOL_SEPARATOR 장식 기호(▶ ◈ ★ 등)를 2개 이상 끼워 낱말을 끊은 것
      KEYWORD_SPACING  한 글자씩 띄어 쓴 낱말(예: 카 지 노)
      CASE_MIX         도메인 끝을 대소문자로 섞은 것(예: cOM)
      DOT_SUBSTITUTION 도메인의 점을 다른 글자로 바꾼 것(예: 。 쩜 (dot))
      DOMAIN_SPACING   도메인 안에 띄어쓰기를 넣은 것(예: C O M)
      KANA_SEPARATOR   한글 글 사이에 일본 가나를 끼운 것
  - report.html : 결과 확인 화면. 브라우저로 열립니다. 인터넷이 없어도 열립니다.
  - debug.json  : 검사한 쪽 목록과 판정 근거(문제 확인용).
  주의: 같은 폴더에 다시 실행하면 이전 결과를 덮어씁니다. 남겨 둘 결과는 --out 으로
        다른 폴더를 지정하거나 미리 복사해 두세요.

6. 결과 확인 화면(report.html) 사용법
  - 위쪽     : 탐지 완료 표시, 검사한 주소·시각·걸린 시간, 검사한 쪽 수, 기법별 검출 수
  - 검출 목록: 건마다 쪽 주소, 위치(CSS 선택자), 근거 원문, 위장을 푼 글자, 판정 근거,
               광고 점수가 나옵니다. 위의 찾기 칸과 기법 선택으로 거를 수 있습니다.
  - 검토     : 건마다 오른쪽 위에서 「광고 확인 / 오탐 / 미검토」를 고릅니다.
               「CSV 내려받기」를 누르면 검토 상태까지 엑셀용 파일로 저장됩니다.
               검토 상태는 그 PC 의 브라우저에만 저장되므로, 공유하려면 CSV 를 보내세요.
  - 쪽별     : 어느 쪽에 검출이 몰려 있는지 봅니다.
  - 업자 묶음: 근거 글자 속 연락처(웹 주소·메신저 아이디·전화번호)가 같은 검출을 묶습니다.
               여러 쪽에 걸친 묶음은 한 업자가 사이트 전반에 뿌린 것일 가능성이 큽니다.
  - 조치 안내: 기법별로 무엇을 지우고 무엇을 점검할지 안내합니다.

7. 검사 방식과 지켜 두면 좋은 점
  - 입력한 주소와 같은 사이트 안의 링크만 따라갑니다(다른 사이트로는 나가지 않음).
  - 사이트의 robots.txt 가 금지한 주소는 열지 않습니다.
  - PDF·HWP·이미지 등 문서·그림 파일은 열지 않습니다.
  - 쪽 4개를 동시에 엽니다(검사 시간 단축). PC 가 느리면 환경변수 ADDETECTOR_WORKERS=2 로 줄일 수 있습니다.
  - 검사는 20분 또는 2,000쪽 중 먼저 닿는 쪽에서 끝납니다(평가 상한 30분에 10분 여유). 작은 사이트는 쪽을 다 보면 바로 끝납니다.
  - 운영 중인 사이트를 검사할 때는 사이트 담당 기관의 허락을 받고, 필요하면 --delay 를 늘리세요.

8. 문제가 생겼을 때
  - 실행하자마자 창이 닫힘   : 명령 창(방법 2)으로 실행하면 오류 문구를 볼 수 있습니다.
  - 브라우저(msedge) 관련 오류: Microsoft Edge 가 설치되어 있는지 확인합니다.
  - 검사한 쪽이 매우 적음     : 주소를 사이트 첫 화면으로 넣었는지, 사이트가 접속을 막지 않는지
                                (robots.txt, 대기열 화면 등) 확인합니다.
  - 결과 화면이 안 열림       : 같은 폴더의 report.html 을 직접 더블클릭합니다.
  - 결과 화면 생성이 실패해도 result.json 은 정상 저장됩니다.

9. API 판 (AI 2차 판정, 선택)
  - 제출 묶음에는 AdDetector_API(API 판) 폴더만 들어 있습니다. 키가 없으면 API 없이 돌므로 이 폴더 하나로 두 방식을 모두 씁니다.
    소스에서 빌드하면 AdDetector(API 없음) 폴더도 만들어지며, 실행 파일은 같고 settings.json 의 "api" 값만 다릅니다.
  - API 판은 숨김·위장 규칙에 걸렸지만 광고인지 애매한 글만 언어 모델(Claude API)에 다시 물어 판정합니다.
    방식은 v2 입니다: 숨김·위장 규칙에 걸렸지만 광고 점수가 애매한 글을 숨긴 방식·링크 주소와 함께 AI 에 묻고,
    AI 가 「확실하다」고 답한 것만 판정을 바꿉니다(광고면 검출에 넣고 정상이면 뺌). 확실하지 않다고 답하면 원래 판정을 그대로 둡니다.
    광고 점수가 아주 낮아도 숨김·위장 규칙에 걸린 외부 링크 글(8자 이상)은 함께 묻습니다(광고 낱말이 없는 홍보 글 대비).
    API 호출이 실패하면 두 번 더 시도하고, 묶음 3개가 연속 실패할 때만 API 없이 판정으로 돌아갑니다.
    확실한 것은 묻지 않고, 같은 글은 한 번만 묻습니다. 한 검사에서 최대 800개 글, API 에 쓰는 시간은 최대 8분입니다.
  - 사용 서비스: Anthropic Claude API (Messages API, https://api.anthropic.com/v1/messages)
    모델명: claude-haiku-5-5 / 환경변수 이름: ANTHROPIC_API_KEY
  - API 키 설정: AdDetector_API 폴더(실행 파일 옆)의 .env.example 을 .env 로 이름을 바꾸고
      ANTHROPIC_API_KEY=발급받은키
    한 줄을 적습니다. 키를 바꿀 때도 이 줄만 고치면 되며 다시 빌드할 필요가 없습니다.
    키 찾는 순서: 환경변수 ANTHROPIC_API_KEY -> 실행 파일 옆 .env -> (예전 방식) api_key.txt
    키는 소스코드·결과 파일에 들어 있지 않습니다. .env 파일을 다른 사람에게 보내지 마세요.
  - 키가 없거나 인터넷이 안 되거나 API 가 실패하면, 자동으로 API 없는 판과 똑같이 판정합니다(결과 파일은 항상 만들어짐).
  - 검사 대상 사이트의 글 일부(애매한 글)가 외부 API 로 전송됩니다. 내부망 사이트를 검사할 때는 담당 기관의 허락을 받으세요.
  - 끝나면 창에 물은 글 수, 호출 수, 걸린 시간, 토큰 사용량이 표시됩니다. 결과 화면에는 AI 가 광고로 판정한 건에 표시가 붙습니다.
  - API 없는 폴더에서도 --api 를 붙이면 API 판으로, API 판 폴더에서 --no-api 를 붙이면 API 없이 돕니다.

10. 모델 교체 (관리자용)
  model_v9n 폴더만 새 모델로 바꾸면 다시 설치하지 않아도 됩니다.
  다른 폴더의 모델을 쓰려면 --model "모델 폴더" 를 붙입니다.
