# 불법광고 탐지 도구: 개발 현황 (2026-10-14)

사람 1(C)이 저장소 밖에서 만들어 온 시험판 탐지 도구를 이 커밋으로 저장소에 넣었다. 이 문서는 무엇이 어디에 있고, 어떻게 돌리며, 지금 어디까지 확인했는지 정리한다. 마감은 2026-10-23(금) 18시다.

평가용으로 떼어 둔 데이터의 결과와 분할 정보는 이 저장소에 넣지 않았다. 탐지 엔진을 맡는 쪽이 평가 데이터를 보지 않게 하기 위해서다. 그래서 아래 성능 수치는 학습 데이터 안의 교차검증과 실제 공공 누리집 측정만 적는다.

## 한눈에

| 항목 | 현재 상태 |
|---|---|
| 동작 | 주소 하나 -> 같은 사이트 크롤링 -> Edge 로 그리기 -> 탐지 -> 요강 형식 `result.json`·`result_extra.json` |
| 학습 데이터 교차검증(요강 4종) | 재현율 85.2%, 정밀도 87.0%, 참고 점수 68.8 / 80. 광고 아닌 DECOY 조각 오탐 0.4% |
| 실제 공공 누리집 | 마지막 측정(처음 보는 5곳, 503페이지) 4종 출력 2건, 페이지당 0.004건. 그 원인까지 고친 뒤 저장 페이지로 다시 대 보면 0건 |
| 진짜 광고 검출 | 부산시 시민 게시판 글 제목 3건(유흥업소 광고, 전화번호 010 을 「OI0」로 위장)을 HOMOGLYPH 로 잡음 |
| 실제 재현율 | **모른다.** 실측에서 찾은 진짜 광고는 부산시 3건뿐이라 재현율을 낼 수 없다. 10-17 에 받을 블라인드 사이트로 잰다 |
| 제출 형태 | Windows exe(PyInstaller onedir, 290MB, 브라우저는 Windows 기본 Edge). 깨끗한 PC·Defender 확인은 아직 |
| AI API | 제출판은 쓰지 않는다(외부 접속 없이 동작) |

참고 점수는 요강에 환산식이 없어서, 복구한 채점기에 적힌 가정(45 x 재현율 + 35 x 정밀도)을 그대로 쓴 값이다.

## 2. 돌리는 법

```
cd A_crawler
python run.py https://점검할.누리집.go.kr/                 # 결과: A_crawler/result.json, result_extra.json, run_log.json
python run.py https://점검할.누리집.go.kr/ --out 결과폴더   # 결과 폴더 지정
bash real_fp.sh https://a.go.kr/ https://b.go.kr/            # 실제 누리집 오탐 측정(사이트당 100페이지, 동시 2창, 10분)
bash ../D_ui_docs/build_exe.sh <저장소 밖 작업 폴더>         # exe 묶기(필요한 패키지만 든 가상환경을 만들어 쓴다)
```

필요한 패키지: scikit-learn 1.5.1(모델 피클과 판을 맞춤), numpy, scipy, pyyaml, playwright. 브라우저는 설치된 Edge 를 쓴다.

## 3. 탐지 방식

| 단계 | 하는 일 |
|---|---|
| 크롤링 | 진입 주소와 같은 사이트 링크를 따라간다. 첫 화면이 다른 호스트로 넘어가거나 스크립트로 늦게 넘어가도 도착한 곳을 대상으로 삼는다 |
| 그리기 | Edge(Playwright)로 페이지와 iframe 을 그리고 요소마다 계산된 스타일·좌표·글자를 뽑는다 |
| 숨김 판정(규칙) | TRANSPARENT: 누적 투명도, 글자색 알파, 배경과의 대비 1.15 미만. OFFSCREEN: display·visibility, 1px 이하 글자, 화면 밖 좌표, text-indent, clip |
| 글자 위장 판정(규칙) | HOMOGLYPH: 전각·원문자·수학 글꼴 등 꾸민 글자, 키릴·그리스 섞기, 닮은 점, 닮은 숫자(「OI0」). JAMO: 풀어 쓴 자모 |
| 내용 판정(모델) | 문자 n-gram 로지스틱 회귀. 숨김·위장 신호가 있는 글이 광고인지 점수를 낸다. GPU 없음 |
| 사이트 단위 후처리 | 같은 위치·기법·글자가 방문 페이지의 30% 이상에 반복되면 사이트 공통 메뉴로 보고, 글자 점수가 0.9 이상일 때만 남긴다 |

정상 사이트의 흔한 숨김을 광고로 보지 않게 넣은 규칙(모두 실측 오탐에서 나왔다):

- 숨긴 관련 사이트·SNS 메뉴: 숨김 영역의 링크가 바깥 호스트 3곳 이상을 가리키면 링크 글자만으로 판정
- 슬라이더: 같은 부모 아래 숨김 영역들은 합쳐서 바깥 호스트를 센다
- 펼침 하위 메뉴: 부모가 보이는 `li` 인 display:none 영역의 외부 링크는 링크 글자만으로 판정
- 아이콘 링크의 접근성 글자(text-indent): 링크 글자만으로도 점수가 넘어야 광고
- 공공 기관 도메인(go.kr, or.kr, gov.kr, 외국 정부 도메인)으로 가는 링크는 외부 광고 링크로 보지 않음
- HOMOGLYPH 예외: 단위 기호 ℃·℉, 한글 없는 외국어판 페이지의 전각 부호, 가운뎃점으로 쓴 ․, 회사 약자 ㈜·㈔
- LINK_CLOAKING 예외: 한 페이지에서 같은 앵커 글자(「바로가기」)가 바깥 호스트 3곳 이상을 가리키면 관련 사이트 목록
- `<script>`·`<style>` 같은 글자 아닌 요소는 숨김 영역에서 뺌

각 규칙은 넣기 전에 학습 데이터에서 그 꼴의 진짜 광고가 있는지 먼저 세고, 교차검증 재현율이 떨어지지 않는 것만 넣었다.

## 4. 실제 공공 누리집 측정

광고가 없다고 보는 공공 누리집을 돌려 오탐을 셌다. 측정마다 오탐 원인을 고쳤고, 고치는 데 쓴 사이트는 다음 검증에 다시 쓰지 않았다.

| 차수 | 사이트(페이지) | 요강 4종 출력 | 추가 유형 출력 | 그 뒤 고친 것 |
|---|---|---:|---:|---|
| 1차 | 정책브리핑 등(100, 넘김 결함으로 4곳 1페이지) | 367 | - | 첫 화면 넘김 결함 |
| 2차 | 5곳(504) | 245 | - | 숨긴 SNS 메뉴 등 규칙 7개 |
| 3차 | 처음 보는 3곳(303) | 114 | 2,098 | 공통 틀 거르기, 링크 목록 메뉴, CSS content·주소 인코딩 오탐 |
| 4차 | 처음 보는 5곳(503) | 75 | 16 | HOMOGLYPH 단위 기호·외국어판·가운뎃점, 슬라이더 |
| 5차 | 처음 보는 5곳(405) | 13 | 4 | 아이콘 링크 접근성 글자, 늦은 스크립트 넘김(크롤러) |
| 6차 | 처음 보는 5곳(503) | 2 | 16 | ㈜·닮은 숫자, 공공 도메인 결함, 펼침 메뉴, 「바로가기」 목록 |

6차까지 고친 뒤 5·6차에서 저장한 페이지로 다시 대 보면 요강 4종 0건, 추가 유형 20건 -> 6건이다. 남은 6건은 처음 보는 정상 사이트로 가는 「바로가기」·「신고하기」 링크(익명신고 서비스, 공개 대시보드, 국가통계포털 등)다. 주소와 글자만 보는 지금 링크 모델로는 스팸 링크와 가를 근거가 없다.

**4차 사이트 재실행(지금 코드, 302페이지)**: 요강 4종 10건 가운데 3건이 진짜 불법광고였다. 부산시 시민 게시판 글 제목 3개에 유흥업소 광고가 올라와 있고, 전화번호의 010 을 「OI0」(영문 O·I + 숫자 0)로 위장했다(번호는 적지 않는다). 나머지 7건은 오탐이다: 첫 화면 소식 칸의 이벤트 안내 2, 로그인 페이지 「브라우저 업데이트」 1, 접힌 자주 묻는 질문 답변 2, 전화번호표의 전각 쌍점 1, 등록 단체 표의 「유흥주점」 1. 추가 유형 15건은 부산시가 바깥 링크를 보안 검사 주소로 감싸 보내는 것이다.

측정에 쓴 26곳은 검증에 다시 쓰지 않는다: 정책브리핑(korea.kr), 행정안전부, NIA, 과학기술정보통신부, 시흥시, 한국공학대, 서울시, 경기도, 국세청, 통계청, 환경부, 부산시, 외교부, 교육부, 기상청, 식약처, 대구시, 보건복지부, 경찰청, 산림청, 특허청, 인천시, 국토교통부, 농림축산식품부, 코레일, 국민건강보험공단.

## 5. OFFSCREEN 점검 (사람 3 새 원본 350건)

`C_data/offscreen/offscreen_originals.yaml`(10-14 갱신, 부유형 7가지 x 50)을 그대로 그려 숨김 규칙을 확인했다.

| 부유형 | 건수 | 숨김 판정 | 정답 위치에 냄 |
|---|---:|---:|---:|
| font_size_zero_or_tiny | 50 | 50 | 43 |
| negative_text_indent | 50 | 50 | 49 |
| clip_or_clip_path | 50 | 50 | 14 |
| display_none | 50 | 50 | 30 |
| negative_left | 50 | 50 | 48 |
| transform_or_document_coordinates | 50 | 50 | 29 |
| visibility_hidden | 50 | 50 | 33 |
| 합계 | 350 | 350 | 246 |

- 숨김 규칙은 350건 모두 숨김으로 본다.
- **사람 3 확인 요청**: clip_or_clip_path 23건(OF-128 등)은 `expected_location` 이 원래 페이지의 선택자(`#post-2294 > ...`)라 html 발췌 안에서 찾을 수 없다. 증거 글자로 요소를 찾으면 23건 모두 숨김으로 잡힌다.
- 정답 위치에 내지 못한 것 가운데 36건은 내용 점수가 숨김 문턱 0.8 에 못 미쳤다(「bokep indo」 0.43, 「Bet On Red」 0.13). 44건은 한 조각에 광고 링크가 여럿이라 정답 말고 다른 광고 링크를 낸 경우가 대부분이다.

**OFFSCREEN 문턱 실험**: OFFSCREEN 만 숨김 문턱을 낮춰 보았다. 실측은 4·5·6차에서 저장한 페이지 재생이다.

| OFFSCREEN 문턱 | 교차검증 참고 점수 | 새 350 정답 위치 | 실측 4종 출력 |
|---|---:|---:|---:|
| 0.8(현재) | 68.8 | 246 | 10 |
| 0.6 | 68.7 | 252 | 36 |
| 0.5 | 68.6 | 254 | 44 |
| 0.3 | 68.2 | 256 | 263 |

낮춰서 얻는 것은 최대 10건인데 실측 오탐은 4~26배가 된다. 늘어나는 오탐은 접힌 안내문이다. 숨긴 정상 한글 안내문이 0.4~0.8 점에, 놓치는 광고 문구가 0.1~0.4 점에 있어 문턱으로는 가를 수 없다. 문턱은 0.8 로 둔다. OFFSCREEN 놓침을 줄이려면 내용 판정이 짧은 한글 광고 문구(「먹튀」, 「스포츠중계」 류)를 알아야 한다. 새 350건은 한글 광고 문구가 1건뿐이라 이 부분을 풀 데이터가 아니다.

## 6. 정한 것

| 결정 | 이유 |
|---|---|
| 제출판은 LLM 을 쓰지 않는다 | 지금까지 모든 측정이 LLM 없이 나왔다. LLM 은 점수 0.35~문턱 사이 후보만 다시 묻는데, 놓치는 문구는 대부분 그 아래다. 심사 환경의 외부 접속 여부를 모른다 |
| 모델을 새로 짜지 않고 지금 구조를 고친다 | 큰 약점이 모델 종류보다 규칙·데이터에서 나왔다. 바꿀 여지가 있는 것은 내용 판정기 하나이고 블라인드 결과로 정한다 |
| 블라인드 사이트를 받으면 그 시점 판을 고정해 먼저 돌린다 | 받은 뒤 고친 판으로 재면 블라인드가 아니다 |

알려진 약점:

- OFFSCREEN 놓침: 짧은 한글 광고 문구의 내용 점수 미달
- LINK_CLOAKING 실측 오탐: 처음 보는 정상 사이트로 가는 「바로가기」 (호스트 평판을 모른다)
- 공통 틀 거르기는 「사이트 전체에 심은 광고는 글자 점수 0.9 이상」을 가정한다. 평범한 이름의 링크를 사이트 전체에 심으면 놓친다
- 실제 재현율은 아직 모른다
