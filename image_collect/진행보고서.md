# 이미지 수집 진행보고서 (채현 몫, 11.3~11.6)

재계획 6절의 채현 몫 가운데 11.6 관문 전까지의 세 가지를 다룬다: 크롤러 이미지 수집, 실제 불법 이미지(R_pos) 시험 수집, OCR 엔진 선택. 한 일마다 근거를 같이 적는다.

> **이 문서 뒤에 일어난 것 (2026-11-17 덧붙임).** 이 보고서는 11-03\~11-06 수집 기록이고 본문은 그때 그대로 둔다. 11-06 관문(실제 불법 이미지 100장 이상)을 통과해 계획 A(실제 이미지 평가셋)로 갔다. 최종 데이터는 사이트 471곳의 실제 이미지 10,001장(R_pos 715 · 일반 9,081 · 정연 어려운 음성 205)이고, 11-09 H2 로 준아에게 넘겼다. 라벨은 v1.2(11-16), 분할은 split_v1(11-10 동결, 학습 3,975 · 검증 3,026 · 평가 3,000장)이다. 모델과 평가 결과는 저장소 첫 README 의 「2차」 절과 `image_models/README.md` 에 있다.

## 2. 수집기 (`tools/collect.py`)

**무엇을 받나.** 씨앗 페이지 하나를 Chromium(Playwright)으로 렌더링하고 끝까지 내려 지연 로딩 이미지를 깨운 뒤, `img`(currentSrc, 없으면 data-src), `input[type=image]`, CSS `background-image` 를 모은다. 같은 등록 도메인의 iframe 안도 본다. 이미지 바이트는 페이지가 실제로 받은 응답에서 가져오고, 없을 때만 리디렉트 없이 직접 받는다.

**무엇을 기록하나.** 명세 5절 meta.csv 의 화면 정보 열(source_url, page_url, site, site_type, element, w, h, render_w, render_h, x, y, selector, link_href, alt, collected_at)을 `occurrences_<샤드>.csv` 에 (페이지, 이미지 요소) 한 쌍마다 한 줄로 남긴다. 선택자는 1차 크롤러(`site_scan.py`)와 같은 방식이다. 숨겨진 요소(display:none, visibility:hidden, opacity 0, 크기 0)는 render_w·render_h 를 0으로 적는다. 페이지마다 보이는 글을 `pages_text_<샤드>.jsonl` 에 같이 남긴다(재계획 1절 「같은 페이지에서 텍스트 요소와 이미지 요소를 함께 기록」).

**접속 범위를 어떻게 지키나.** 재계획 3절 수집 원칙을 코드로 옮긴 것:

| 원칙 | 구현 |
|---|---|
| 불법 사이트로 이동하지 않는다 | 씨앗 주소를 먼저 리디렉트 없이 물어 다른 등록 도메인으로 3xx 하면 열지 않는다. 렌더링 중 메인 프레임이 다른 등록 도메인으로 가려 하면(JS, meta refresh) 그 요청을 끊는다 |
| 링크를 따라가지 않는다 | 씨앗 페이지만 연다. 링크는 link_href 에 적기만 한다. 팝업 창은 열리자마자 닫고 다운로드는 받지 않는다 |
| 피해 페이지에 박힌 외부 이미지는 받는다 | 이미지·CSS·스크립트 같은 하위 자원은 막지 않는다 |
| (보수적으로 더한 것) | 다른 등록 도메인의 iframe 문서는 끊는다. 불법 사이트 페이지를 통째로 끼워 넣는 경우가 있어서다. 이 때문에 놓친 이미지가 있을 수 있다 |
| robots.txt, 1초 간격 | 씨앗 페이지 호스트와 직접 받는 이미지 호스트의 robots.txt 를 1차와 같은 판정으로 지킨다. 페이지 사이 1초 |
| 성인 이미지는 저장하지 않는다 | 저장 전에 메모리에서 공개 분류기(Falconsai/nsfw_image_detection)로 점수를 내 0.30 이상이면 버리고 skipped.csv 에 adult 로 남긴다. 사람이 열어 보지 않게 하려는 것이라 문턱을 낮게 잡았다. 잘못 버린 비율은 파일이 없어서 잴 수 없다(보고서 한계) |
| 32px 미만은 저장하지 않는다 | 가로나 세로가 32px 미만이면 too_small |

**파일 이름.** `images/<SHA-1 앞 16자리>.<확장자>`. 접두어는 H2 export 때 붙인다. 11-06 에 `rimg_` 하나로 합쳤다(4.9절). SVG 는 브라우저로 그려 PNG 로, BMP·ICO 는 PNG 로 바꿔 저장한다.

**알려진 흠.** (1) 1차 dev_data 의 source 칸 주소에 `&amp;` 가 섞여 있어 이번 실행의 씨앗 일부는 그 주소 그대로 열었다. 게시판 주소라 대부분 같은 페이지가 열리지만, 씨앗 만드는 코드는 고쳐 두었다(다음 실행부터 적용). (2) `fail_*.csv` 의 `decode:` 사유에는 이미지를 받는 단계의 연결 오류도 섞여 있다(받기와 풀기를 한 try 로 묶음).

**씨앗.** 1차 dev_data 에서 숨은 스팸이 실측된 도메인 439곳 가운데 도메인 자체가 도박·SEO 업자 것으로 보이는 24곳을 빼고, 도메인마다 최대 2쪽, 550쪽(`seeds_dev.csv`). 여기에 검색으로 찾은 피해 페이지 41쪽(`seeds_search.csv`: 인도네시아 대학 학술지, 뉴스 사이트의 스폰서 글, 사용자 글 플랫폼에 심긴 홍보 글)을 더해 591쪽이다. 이 591쪽을 돈 뒤, 무작위 표본에서 한국어 게시판 스팸 배너가 나와 그 배너가 나온 종류의 한국어 게시판 도메인 73곳의 다른 1차 실측 페이지 292쪽(도메인당 최대 6쪽, `seeds_more.csv`)을 더 돌았다. 모두 883쪽이다. 검색 도구가 한국어 도박 추천 질의 일부를 거절해서 검색 씨앗은 외국어 쪽에 치우쳐 있다.

## 3. OCR 엔진 선택 (`ocr_select/`)

**고른 것: PaddleOCR 3.7.0, PP-OCRv5_mobile_det + korean_PP-OCRv5_mobile_rec.** 설정 전체는 `ocr_select/OCR_FIXED.txt`, 코드는 `tools/ocr_engines.py` 의 `Paddle`.

**어떻게 골랐나.** 재계획 3절 분리 규칙대로 실제 수집 이미지는 정확도 비교에 쓰지 않았다. 정답 글자를 아는 합성 배너 160장(`make_synth.py`, 시드 20261104)을 만들었다. 문구는 1차 dev_data 의 스팸 문구 조각 96개와 일반 문구 64개이고, 크기 4종, 글꼴 8종, 배경 3종, 외곽선, 그림자, 기울기, JPEG 품질 35~90 을 섞었다. 글자 오류율(CER: 편집 거리 / 정답 글자 수, 빈칸과 대소문자는 무시)과 이미지당 시간(CPU, 첫 장 제외)을 쟀다.

| 엔진 | 한국어 (70장) | 한영 섞임 (27장) | 영어·인도네시아어 (63장) | 전체 (160장) | 이미지당 시간 |
|---|---|---|---|---|---|
| EasyOCR 1.7.2 | 0.047 | 0.139 | 0.063 | 0.069 | 0.19초 |
| PaddleOCR, server 검출 | 0.019 | 0.031 | 0.004 | 0.015 | 1.11초 |
| **PaddleOCR, mobile 검출 (채택)** | 0.010 | 0.033 | 0.004 | 0.012 | 0.33초 |

- EasyOCR 대 채택: 짝지은 CER 차이 0.058, 부트스트랩 2,000회 95% 신뢰구간 [0.042, 0.075]. 160장 중 채택이 나은 것 56장, 같은 것 104장, 나쁜 것 0장.
- server 검출 대 mobile 검출: 차이 0.003, 95% 신뢰구간 [-0.001, 0.008]로 0을 포함한다. 정확도는 같은 수준으로 읽어야 하고, mobile 을 고른 근거는 속도다.

**고르는 도중 바뀐 것 (11-04 하루 안).** 처음에는 PaddleOCR 기본 설정(server 검출)으로 정했다. 그런데 실제 이미지에 돌려 보니 25분 동안 59장밖에 못 읽었다. 이 PC 의 Paddle 3.3 은 CPU 가속(oneDNN)을 켜면 PP-OCRv5 모델에서 오류가 나서 가속을 껐는데, 가속 없는 server 검출 모델은 빈 1600px 이미지 한 장에 16.8초가 걸렸다(mobile 검출은 1.7초). 그래서 mobile 검출로 바꾸고 합성 160장을 다시 쟀다(위 표). 큰 이미지(긴 변 최대 8,208px)를 위해 두 가지 제한도 더했다. 검출 입력의 긴 변은 1,280px 까지로 하고, 입력 이미지의 긴 변이 1,600px 를 넘으면 OCR 전에 1,600px 로 줄인다. 글상자 좌표는 원본 크기로 되돌려 적는다. 합성 배너는 모두 728px 이하라 두 제한 모두에 걸리지 않는다. 이 과정에서 실제 이미지는 속도를 재는 데만 썼고 내용이나 라벨은 쓰지 않았다.

**한계.** 합성 배너는 깨끗한 시스템 글꼴이라 실제 배너(장식체, 작은 글씨, 사진 위 글자)보다 쉽다. 엔진 순위는 세 언어 묶음 모두에서 같았지만, 실제 이미지의 오류율은 이 표보다 높을 것이다. 실제 오류율은 준아의 선택 항목(평가 이미지 50장 받아 적기)으로만 잴 수 있다.

### 4.2 어떻게 셌나

이미지 5,196장을 모두 눈으로 볼 수는 없어서, 신호 두 가지로 후보를 추려 후보만 봤다.

1. **링크·주소 신호 (후보 B, 147장).** 이미지를 감싼 링크, 이미지 주소, alt 에 도박 낱말이 있는 것. 116장이 illegal.
2. **OCR 글 신호 (후보 C, 174장).** 고정한 OCR 로 읽은 글에 도박·불법 홍보 낱말(가입코드, 텔레, 총판, 홀덤, slot, gacor 등)이 있는 것 중 B 가 아닌 것. 118장이 illegal.
3. **표본 (SA, 100장).** 도박 낱말이 많은 페이지(243쪽)의 이미지 중 B 가 아닌 2,217장에서 무작위로 100장. 4장이 illegal 이었다. 4장 모두 한국어 게시판 스팸 배너이고 OCR 신호로는 잡혔다.

**놓친 양 추정.** unsure=0 인 illegal 206장 가운데 B 신호가 있는 것 87장, OCR 신호가 있는 것 194장, 둘 다 있는 것 75장이다. 두 신호가 서로 독립이라고 보면(포획-재포획, Chapman 추정) 수집한 이미지 안의 확실한 illegal 은 약 225장이다. 그렇다면 두 신호 모두에 안 걸려 못 본 것은 20장 안팎이다. 두 신호가 독립이라는 가정은 확인하지 않았다. 영어 로고는 B 에만, 한국어 배너는 OCR 에만 걸리는 식으로 이미지 종류에 따라 갈리기 때문에 이 추정은 대략적인 값이다. OCR 신호의 재현율은 B 의 확실한 illegal 87장 중 75장(86%, Wilson 95% 구간 77~92%)이다.

### 4.4 짚어 둘 것 (팀에 알릴 것)

1. **라벨은 초안이다.** 모아보기 판(`logs/sheets/B_*`, `C1_*`, `C2_*`, `SA_*`)을 보고 붙인 것이다. 판정 기준은 `tools/labels_B.py` 머리말의 임시 기준이고 준아의 가이드라인 v1(11.5)이 나오면 다시 맞춘다. unsure=1 로 둔 것은 슬롯 게임 제목 그림만 있고 사이트·홍보 문구가 없는 것, 칩·슬롯 아이콘, 가입 단추만 있는 것, 일부만 보이는 로고다. 이것들을 illegal 로 볼지는 가이드라인에서 정해야 한다.
2. **분할 그룹에 연락처를 더하자고 제안한다 (명세 10절 열린 질문).** 한국어 스팸 배너는 같은 업자가 그림을 바꿔 여러 사이트에 뿌린다. OCR 글의 전화번호·텔레그램 아이디로 이으면 illegal 238장이 180묶음이 되고, 가장 큰 묶음은 25장이 7개 사이트에 걸쳐 있다. 명세대로 사이트·pHash 로만 묶으면 이 25장이 학습과 평가로 갈라질 수 있다. 연락처가 같으면 같은 그룹으로 잇는 조건을 하나 더하는 것을 준아에게 제안한다.

**전체 점검 (11-06):** 다음을 찾아 고쳤다. (1) `make_split.py` 는 정연 meta 처럼 `phash` 가 일부만 빈 행을 조용히 건너뛰었다. 지금 데이터에서 영향 쌍은 없지만 `--img-root` 로 계산하거나 경고하게 했다. (4) `seed.txt` 는 표본 구성이 있어 정연에게 주지 않고 H2 때 준아에게 준다. 명세도 고쳤다. κ 의 R_pos 표본은 채현 미확인 479장에서만 뽑아 불법 전체와 구성이 다르다. Excel 로 κ 엑셀을 열어 그림 343장과 드롭다운을 확인했다.

**점검 엑셀 변경 (11-06):** 판정 칸 기본값 「맞음」을 없앴다. 안 본 줄을 맞음으로 세지 않기 위해서다. 집계는 본 줄만 세고, 틀림이 0 이어도 95% 상한(약 3/n)을 함께 적는다.

**H2 묶음 (11-09):** 채현 κ 343장과 점검 200장(맞음 198, 틀림 0, 모름 2)을 반영해 `deliver/h2` 와 바탕화면 `준아_H2.zip`(1.45GB, 9,807개, testzip 통과)을 만들었다. meta 9,796장: illegal 715(unsure=0 579, 1 136), legal_ad 96, campaign 9, normal 8,976. labeler: Claude규칙초안 6,357, Claude초안 2,551, Claude초안+채현확인 545, 채현 343. 점검은 표본이 100장씩이라 틀림 0이어도 오류율 상한이 약 3%다. 정연 meta 를 합쳐 거리 4로 분할하면 전체 60.5/19.6/19.9, 불법 unsure=0 408/90/81, legal_ad 84/33/75, campaign 43/12/14 이고 가장 큰 그룹 g00007 이 불법 246장(42%)을 가진다. 라벨 반영 전에도 같은 그룹(불법 193장)이었다. `make_split.py` 는 `--img-root` 아래 이미지를 못 열면 조용히 빠지던 것을 경고하게 고쳤다. 원본과 정연 이미지가 한 폴더 아래 있어야 정연 156장의 pHash가 계산된다. 지금 데이터에서는 156장을 넣어도 pHash 연결 수(113)는 같았다. κ 의 개별 판정은 Claude 가 보지도 고치지도 않았고 형식만 검사했다(전체 분포에는 합쳐져 있다).

**정연 2차 전달 반영 (11-09):** 정연이 26장 수정, site_type(police.go.kr 1건), lang, 추가 수집 50장(합법 대출·경마/경륜/경정·계도), κ label_b 343장을 보냈다. 원래 156장 중 72번(kcgp 「가정통신문」 표지, campaign)은 설명 없이 빠졌다. v1 로는 campaign 이 아니라 normal 이고, 불법 양성이 아니어서 채점 양성에는 영향이 없다. `tools/merge_hard_v2.py` 로 R_add 를 R_hard, radd_ 를 rhard_ 로 맞추고, 추가 50장 labeler 를 Claude초안+정연확인으로, 새출발기금 안내 1장을 v1 에 따라 normal(채현)로 바꿨다. 추가 50장은 OCR 을 돌려 ocr_hard.csv 를 205장으로 만들고 lang 을 채웠다. 추가분 중 6장은 정연이 찍은 스크린샷 크롭이라 img 요소 단위가 아니다(note 에 표시). κ: 4종 0.772, 불법 여부 0.963, 둘 다 unsure=0 인 286장에서 불법 여부 1.0, unsure 일치 0.872. 갈린 84장 중 라벨이 다른 것은 채현 normal / 정연 legal_ad 33장이 가장 많다. 정연은 「일반 상업 광고는 normal」 임시 기준을 받지 않았다. 묶음은 `준아_H2.zip` 1.54GB 로 다시 만들었고 이미지 10,001장이다. 합쳐 분할하면 불법 unsure=0 408/92/79, legal_ad 88/28/77, campaign 57/19/19.

**최종 점검 (11-09):** zip 과 deliver/h2 목록·크기 일치(10,021개), 이미지 10,001장 해시 전부 일치, id·sha1·file 중복 0, 라벨 규칙 위반 0, OCR·ocr_boxes 가 두 meta 와 정확히 같은 id, κ 재계산 값이 묶음과 같음, 점검 결과가 meta 에 반영됨. kappa_order.csv 는 9,406행 전체 순위표이고 κ 343장은 각 묶음의 앞 순위(R_pos 0\~142, R_gen 0\~199)와 정확히 일치한다. 분할 -> B0 -> 채점(val) 을 묶음 파일만으로 끝까지 돌렸다. **B0(이미지 안 보고 크기·화면 크기·확장자·이미지 서버만 보는 모델)의 val PR-AUC 가 0.334 로 무작위 기준 0.048 의 7배다.** 중요 특징은 render_h 0.220, render_w 0.153, log_area 0.099. 정연 R_hard 는 render 가 비어 있다. > 처음에 「생김새 밖 단서가 새는 것으로 보인다」고 적었으나 아래 재측정으로 고친다.

**B0 재측정 (11-09):** 이미지 모델이 받지 않는 화면 크기(render)를 빼고 같은 분할·unsure=0 으로 다시 쟀다(부스팅, 시드 3개 평균, val 양성 비율 0.048). render 포함 0.247, 원본 w·h·가로세로비 0.088, 짧은 변만 0.104, 가로세로비만 0.039. B0 신호 대부분은 render 에서 오고, 이미지 모델이 볼 수 있는 원본 해상도로는 무작위의 약 2배다. 짧은 변 중간값은 정상 250, 불법 600. 해상도는 크기 조정 뒤 흐림 정도로만 남으므로 큰 문제로 보지 않고 준아에게는 B0 수치 해석만 한 줄 알린다.
