## 2. 수집 방법

1. 검색엔진에서 `site:go.kr / ac.kr / or.kr` + 광고 어휘로 감염된 공공 페이지를 찾았다.
2. 감염된 **게시판 목록 페이지를 순회**했다. 스팸 글 제목에 위장 문자가 그대로 들어 있어 가장 효과적이었다. 예: ypcd.or.kr 8,700쪽, hannam 400쪽.
3. 공공기관 **검색결과 반사 페이지**도 받았다. 스패머가 기관 검색 URL에 광고 문구를 넣어 검색엔진에 색인시킨 페이지다. 예: easylaw, motir, mois, mohw, gangnam.
4. 받은 HTML을 자동 스캔해 후보를 뽑았다. 그다음 중복을 제거하고 등급을 나눠 팀 양식으로 변환했다.

수집 규칙:
- robots.txt를 지켰고 요청 간격은 1.5초다.
- 403/429 응답이나 robots 차단은 우회하지 않았다.
- 공공 도메인만 대상으로 했고, 광고가 가리키는 불법 사이트에는 접속하지 않았다.
- robots 차단으로 HTML을 받지 못한 실재 사례 약 10건(privacy.go.kr, safetv, nongsaro 등)은 포함하지 않았다.

## 5. 필드 설명

팀 공통 필드(`id, category, subtype, html, css, evidence_text, expected_location, is_positive, extra_finding, source, notes`)에 아래 필드를 추가했다.

| 필드 | 의미 |
|---|---|
| `html` | 원본 페이지에서 광고가 든 요소만 잘라낸 조각 |
| `expected_location` | 위 `html` 조각 기준 CSS 선택자 (조각 안에서 유일) |
| `page_location` | **원본 페이지 전체** 기준 선택자 (참고용, 원본 페이지 구조가 바뀌면 달라질 수 있음) |
| `origin.url` / `origin.host` | 수집한 원본 URL / 호스트 |
| `origin.page_id` | 원본 HTML 파일 식별자 (원본 HTML은 사람 2가 보관, 필요하면 요청) |
| `campaign` | 같은 광고 묶음 키 (연락처·도메인 토큰 기준). 연락처로 묶은 것은 `phone:` 뒤에 번호 대신 짧은 해시를 쓴다(6절) |
| `tier` | A/B 확신 등급 (3절) |
| `source_type` | 모두 `real` |

`extra_finding`은 전부 `null`이다. 한 요소에 여러 기법이 겹친 사례는 따로 표시하지 않았다.

## 6. 개인정보 처리

- 휴대폰 번호는 가운데 자리를 가렸다. 일반 숫자뿐 아니라 `O1O`처럼 글자로 바꾼 번호, 전각·원문자·수학 숫자로 쓴 번호도 가렸다.
- 가릴 때는 **위장된 모양을 유지한 0**(예: 전각이면 `０`)으로 바꿔서 탐지 대상 문자는 그대로 남겼다.
- 10-13 수정: `campaign` 칸이 `phone:010` 뒤에 번호 가운데 4자리를 담고 있어서, 번호 대신 8자리 해시(`phone:1a7c1ecb` 식)로 바꿨다. 같은 번호는 같은 해시라 캠페인 묶음과 개수(130)는 그대로다.
- 원본 URL에는 광고 문구가 그대로 들어 있을 수 있다. 공개 저장소에 올릴 때 주의해야 한다.

## 7. 수집하면서 확인한 사실 (보고서 발견 사항 후보)

- 실제 위장 분포는 계획서 쿼터와 다르다. 실제로는 **연락처 숫자↔문자 치환, 원문자·수학 영숫자**가 주류다. 키릴 문자는 드물다.
- 위장은 주로 **연락처·도메인**에 집중된다. 본문 SEO 키워드는 대체로 위장하지 않는다.
- **TRANSPARENT 실제 사례는 0건**이다. 감염 페이지 수십 개를 확인했는데, 실제 스팸은 숨길 때 투명 처리가 아니라 `display:none`을 썼다(OFFSCREEN 쪽).
- 키릴 도메인 비아그라 캠페인(`a2233.cоm` 등)은 여러 대학 게시판에서 발견됐지만 게시판 자체가 이미 삭제되어 수집하지 못했다.
- 제외한 것: 러시아어 스팸(키릴 문자로만 된 문장)은 위장이 아니라 외국어라서 뺐다.
