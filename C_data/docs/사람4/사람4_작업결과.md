# 사람 4 — JAMO·LEXICON 작업 결과

## 1. 핵심 결과

| 데이터셋 | 수량 | 구성 | 상태 |
|---|---:|---|---|
| JAMO | 158건 | 직접 관측 135건 + 실제 광고 기반 파생 23건 | 네 자모 유형의 기존 목표 충족 |
| LEXICON | 500개 | 5개 분류 × 100개 | 사용자 일괄 승인 완료 |

JAMO의 직접 관측본은 `actual_web_observation`, 파생본은
`actual_public_web_observation`으로 구분했다. 파생본은 서로 다른 실제 광고 원문을
보존한 채 실제 키워드만 호환자모로 변환한 자료이며, 자연 발생 자모 광고로 간주하지
않는다. 원문 URL과 파생본의 `parent_id`를 함께 보존했다.

## 2. JAMO 구성

### 자모 유형

| 유형 | 직접 관측 | 파생 | 합계 |
|---|---:|---:|---:|
| 호환자모 전체 분해 (`compat_full`) | 17 | 23 | 40 |
| 단어 중간 부분 혼입 (`partial_mix`) | 43 | 0 | 43 |
| 조합자모 U+1100대 (`conjoining_u1100`) | 20 | 0 | 20 |
| 자모+다른 기법 중첩 (`mixed_technique`) | 55 | 0 | 55 |
| **합계** | **135** | **23** | **158** |

네 유형의 수량 목표는 충족했지만, 자연 발생 `compat_full`은 17건뿐이다. 따라서 실제
웹 환경 탐지 성능을 평가할 때는 직접 관측 17건과 파생 23건의 결과를 분리해야 한다.

### 유해 범주 부족과 데이터 쏠림

다음 표의 40건은 기존 승인 기준이 아니라, 다음 수집 단계에서 사용할 **범주별 최소
균형 목표(제안)**다.

| 유해 범주  |   직접 관측 |     파생 |      합계 |       비율 |
| ------ | ------: | -----: | ------: | -------: |
| 불법금융   |      70 |      0 |      70 |    44.3% |
| 도박     |      35 |      5 |      40 |    25.3% |
| 위조상품   |      29 |      7 |      36 |    22.8% |
| 성착취    |       1 |     11 |      12 |     7.6% |
| **합계** | **135** | **23** | **158** | **100%** |

현재 불법금융은 성착취보다 약 5.8배 많다. 성착취 12건 중 11건이 파생본이고 모두
`ygen.kr` 원문이므로, 단순 수량뿐 아니라 자연 발생 여부와 출처 독립성도 부족하다.
이 상태로 학습·평가하면 다음 문제가 생길 수 있다.

- 전체 정확도가 다수 범주인 불법금융 성능에 의해 과대평가될 수 있다.
- 모델이 유해성보다 특정 사이트 문체·HTML 구조·광고 템플릿을 학습할 수 있다.
- 성착취처럼 표본이 적은 범주의 재현율과 오탐률이 표본 몇 건에 따라 크게 달라진다.
- 파생 자료가 test에 들어가면 자연 발생 광고에 대한 성능처럼 오해될 수 있다.

### 쏠림 해결 우선순위

1. 불법금융 신규 편입은 일시 중지하고, 서로 다른 사이트의 **자연 발생 성착취 28건**과
   위조상품 4건을 우선 수집한다.
2. 한 번의 수집에서 도메인당 최대 3건만 편입하고, 이미 비중이 큰 `emk.kr`와
   `ygen.kr`보다 신규 사이트 계열을 우선한다.
3. 범주×자모 유형×사이트 계열 표를 수집 대시보드로 사용하고, 가장 빈 칸부터 채운다.
   연락처만 다른 동일 템플릿은 새 표본으로 우선하지 않는다.
4. 파생본은 학습 보조 또는 별도 실험에만 사용하고, 최종 test는 직접 관측 자료로만
   구성한다. 파생본을 쓸 때는 실제 자료만 사용한 결과도 함께 보고한다.
5. 학습 시 class weight 또는 소수 범주 oversampling은 **train 내부에서만** 적용한다.
   test 분포는 조작하지 않고 범주별 precision·recall·F1과 macro-F1을 함께 보고한다.

## 3. 수집 공정성·출처 다양성

여기서 공정성은 모든 후보에 같은 포함·제외 기준을 적용했다는 뜻이다. 성별·연령·지역
등 보호 속성이 없어 인구집단별 공정성이나 차별 여부를 검증한 데이터는 아니다.

- 공개 페이지에서 자모 표현과 유해 광고 문맥을 함께 확인한 경우만 포함했다.
- 검색어 자동 정규화 결과, 게시물 밖 메뉴 문구, 정상 토론·후기, 뉴스·예방문·사건
  보도, 원문을 확인할 수 없는 결과는 제외했다.
- URL·관측일·접근 방식·원문·분류 근거를 행 단위로 기록했다.
- 부모 원문 URL 158개는 모두 다르다. URL뿐 아니라 원문·연락처·템플릿 기준의 근접
  중복도 분할 전에 같은 그룹으로 묶어야 한다.

부모 원문은 20개 호스트에서 확보했으며 DCInside 웹·모바일을 합치면 19개 사이트
계열이다. 그러나 `emk.kr` 49건(31.0%)과 `ygen.kr` 43건(27.2%)이 전체의 58.2%, 상위
5개 호스트가 77.8%를 차지한다. 따라서 사이트 개수만으로 출처가 균형 잡혔다고 볼 수
없다.

원문 확인 수준은 전체 본문 135건(85.4%), 제목 18건(11.4%), 검색 결과 5건(3.2%)이다.
`access_status`로 수준을 구분했으며, 제목·검색 결과 확인 사례를 제외한 결과도 별도로
계산할 수 있다.

## 4. train/test 분리

현재 158건은 데이터 풀이며 아직 공식 split 파일은 없다. 다음 검증을 통과한 뒤에만
“train/test 분리 완료”로 표시한다.

1. 동일 URL, 원문·정규화문 중복, 연락처와 문구 틀이 유사한 광고, 원본과 파생본을
   하나의 `group_id`로 묶는다.
2. 같은 그룹과 같은 사이트 계열은 한 split에만 배정한다. test는 가능하면 학습에 없는
   사이트 계열을 통째로 보류하는 site-group holdout으로 만든다.
3. 파생 23건은 test에서 제외하며, 자연 발생 직접 관측본만 최종 평가에 사용한다.
4. 어휘·정규화 규칙은 train에서 확정하고 test를 본 뒤 수정하지 않는다. 조정에는 train
   내부 validation set을 사용한다.
5. 그룹 기준 train 80%·test 20%를 권장하되, 정확한 비율보다 사이트·템플릿 격리를
   우선한다.
6. URL·`group_id`·원문·정규화문의 train/test 교집합이 하나라도 있으면 검증 실패로
   처리한다.

## 5. YAML과 가상 사이트

- 직접 관측 135건: `data/samples/jamo_dataset.csv`, `data/samples/jamo.yaml`
- 파생 23건: `data/actual_derived/data/samples/jamo_dataset_actual_derived.csv`,
  `data/actual_derived/data/samples/jamo_dataset_actual_derived.yaml`
- 파생 원문 근거: `data/actual_derived/data/samples/actual_derived_sources.csv`
- 검증 보고서: `data/review/jamo_dataset_report.json`

직접 관측본과 파생본은 출처 성격이 달라 하나의 YAML로 합치지 않았다. 두 YAML 모두
광고 문구를 새로 생성하지 않으며, 원문·분류·출처와 파생 여부를 보존한다.

CSV와 YAML의 `site_url`은 로컬 경로가 아닌
`https://jamo-actual-derived-23.sassy-bee-2071.chatgpt.site/derived/posts/...` 형식이다.
따라서 다른 컴퓨터에서도 같은 주소를 사용한다. 사이트는 `public` 접근 모드이므로
ChatGPT 로그인이나 별도 암호 없이 누구나 링크를 열 수 있다.

오프라인 사본은 `data/actual_derived/actual_derived_virtual_site.zip`이다. ZIP 내부의
HTML·CSS 링크는 상대 경로이므로 받는 사람이 압축을 풀고 `index.html`을 열면 되며,
Python·인터넷 연결·`localhost`가 필요 없다.

## 6. LEXICON

LEXICON은 탐지용 단어·구문 자산이며 모델의 test set이 아니다.

| 분류 | 개수 |
|---|---:|
| 도박 핵심어 | 100 |
| 도박 유인어 | 100 |
| 접촉수단 | 100 |
| 성인어 | 100 |
| 화이트리스트 | 100 |
| **합계** | **500** |

분류별 수량은 같지만 동일 어근 변형과 일부 출처의 반복 가능성은 남아 있다. 실제 게시판
근거와 공공기관 자료를 함께 사용했으며, 기관 문서의 용어는 광고 양성 표본이 아니라
용어 사용 및 화이트리스트 문맥의 근거로만 취급했다. 500개는 사용자 일괄 승인 결과로,
독립 평가자 다수의 교차 검수는 아니라는 한계가 있다.

주요 산출물은 `data/lexicon/seed.yaml`, `data/lexicon/reviewed.yaml`,
`data/lexicon/review_metadata.json`, `data/lexicon/review.csv`다.
