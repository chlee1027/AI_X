# 사람1 데이터 수집·출처 분류·쏠림 검증 및 생성 아이디어

정리일: 2026-10-13
주제: 공공사이트 불법 광고 탐지
담당 범위: DECOY(정상 요소, 오탐 확인용) · ETC(요강 4종 밖의 숨김·회피 수법) · 조합(수법 2개 이상이 겹친 광고)
기준: 팀 저장소 `C_data/` 의 현재 파일(`decoy/decoy.yaml` · `etc/etc.yaml` · `combo/combo_real.yaml`). 같은 날 DECOY 를 516 에서 816 으로 늘렸고(커밋 `a4eba54`), 이 문서의 DECOY 수치는 816 기준으로 고쳤다. 고치기 전 수치는 각 자리 아래 인용 블록에 남겼다.

이 문서는 화요일까지 할 일 두 가지에 답한다.

1. 수집한 데이터의 출처를 찾아 분류하고, 쏠림이 있는지 검증한다. 쏠림이 있으면 중요도를 어떻게 판단할지 의견을 낸다(2~5절).
2. 덜 모인 데이터를 어떻게 만들어 낼지 고민한다. 공공사이트 불법 광고 탐지라는 주제에 맞춰 아이디어 중심으로 적는다(6절).

용어:
- **양성**: 숨겨진 불법 광고라 탐지기가 잡아야 하는 사례. **음성**: 광고가 아니라 잡으면 안 되는 사례.
- **사이트**: 출처 주소의 호스트(`www.`·`m.` 를 뗀 것). 예: `www.guro.go.kr` -> `guro.go.kr`.
- **실효 사이트 수**: 건수가 사이트마다 고르게 나뉘어 있다면 몇 곳에서 온 것과 같은지를 나타내는 값(1 ÷ 사이트별 비중 제곱의 합). 사이트가 100곳이어도 한 곳이 절반을 차지하면 4 정도로 떨어진다.
- **공공 도메인**: 주소 끝이 `go.kr`(정부·지자체) · `ac.kr` 등(교육) · `or.kr`·`re.kr`(비영리·연구)인 것.

### 출처 성격 쏠림: 크다

- **양성은 민간 사이트, 음성은 공공 사이트에 몰려 있다.** 공공 도메인 비중은 DECOY 50% · ETC 12% · 조합 10% 이고, ETC 에는 정부 도메인(go.kr)이 0건이다. DECOY 는 보충 전 68% 에서 50% 로 내려왔다.
- **게시판 엔진도 갈린다.** 양성은 그누보드(ETC 62% · 조합 65%)와 카페24 게시판, 음성은 전자정부·자체 JSP 와 자체 제작 사이트다. DECOY 의 그누보드는 보충 전 4건뿐이었고, 보충 300건 가운데 201건이 그누보드 게시판에서 나와 205건이 되었다(근사 규칙, 3절).
- **이 쏠림이 실제로 해로운지 재 봤다.** 광고 내용은 보지 않고 「도메인 성격」과 「게시판 엔진」만으로 양성·음성을 맞히게 했다. 맞히는 사이트는 학습에서 빼고 셌다.

### 수법·업종 쏠림

- **ETC 는 보이지 않는 글자가 65%(306/473)다.** 그 가운데 소프트 하이픈(U+00AD) 한 종류만 쓴 것이 238건(77.8%)이고, 이 238건은 사이트 63곳에서 왔다. 업종은 도박 134 · 약물 101 이다.
- **css_content 1건, Base64 3건**으로 드문 수법은 실례가 거의 없다. 한국어 광고 문구를 Base64 로 숨긴 실례는 0건이다.
- **숨김과 난독화가 겹친 조합은 1건**(같은 색으로 숨긴 해시태그 속 「#ㅌㅌ사이트」)이다. 조합 529건의 정답 코드는 HOMOGLYPH 398 · JAMO 20 · TRANSPARENT 1 이라, 조합은 사실상 닮은꼴 글자 쪽에 몰려 있다.
- **업종**은 ETC 가 도박·약물(74%), 조합이 도박(60%)·성매매(27%)다.

## 5. 중요도 판단 아이디어

쏠림이 있을 때 「몇 건 모았나」로 중요도를 정하면 많이 모인 쪽이 과대평가된다. 아래는 건수 대신 쓸 수 있는 기준이다.

### 5-1. 건수가 아니라 독립된 증거 단위로 센다

- 한 사이트·한 업자에서 나온 여러 건은 같은 틀을 복사한 경우가 많다. 사이트 묶음마다 가중치를 `1 ÷ √(그 사이트 건수)` 로 주면, 10건짜리 사이트는 1건짜리 사이트 3.2곳 몫이 된다. 1건짜리 사이트(ETC 53곳)가 상대적으로 무거워진다.
- 평가 점수는 두 가지를 같이 낸다. **건수 기준 재현율**과 **사이트별 재현율의 평균**. 둘이 크게 다르면 탐지기가 몇몇 큰 사이트에만 맞춰져 있다는 뜻이다.

### 5-2. 공공 사이트 출처를 따로 본다

- 대회 평가는 주최 측이 만든 공공 사이트로 한다. 공공 도메인에서 나온 양성(ETC 57 · 조합 51)은 평가 환경과 가장 닮은 데이터라, 결과를 따로 떼어 보고 한다.
- 4절의 지름길 검사를 탐지기 점검 항목으로 둔다. 탐지기에 같은 광고 글을 그누보드 틀과 전자정부 게시판 틀에 각각 넣어 줬을 때 판정이 바뀌면, 내용이 아니라 틀을 보고 있다는 증거다(6-2 의 생성 데이터가 이 검사 재료가 된다).

### 5-3. 세 축으로 하위 유형의 우선순위를 매긴다

| 축 | 질문 | 재는 법 |
|---|---|---|
| 실제로 얼마나 나오나 | 공공 사이트에서 실제로 쓰이는 수법인가 | 수집 중 만난 사이트 수(건수가 아니라) |
| 놓치면 얼마나 아픈가 | 공공기관 사이트에 남으면 피해가 큰가 | 업종(도박·약물·성매매는 큼), 위치(본문·메타는 검색엔진에 노출) |
| 지금 탐지기가 잡기 어려운가 | 단순 글자 검사로 안 걸리는가 | 정규화 전 글자열에 광고어가 그대로 있는지 |

| 하위 유형 | 실제 빈도 | 피해 | 탐지 난이도 | 우선순위 |
|---|---|---|---|---|
| 보이지 않는 글자(zero_width) | 높음(사이트 72곳) | 큼 | 낮음(지우면 끝) | 중 |
| 링크 목적지 숨김 | 중간(53곳) | 큼 | 중간(목적지를 풀어야 함) | 상 |
| 인코딩(퍼센트·엔티티) | 중간(30곳) | 큼 | 중간 | 상 |
| 메타 태그 숨김 | 낮음(3곳) | 큼(검색 결과에 그대로 노출) | 낮음 | 상(부족) |
| css_content · Base64 | 매우 낮음·낮음(1곳·3곳) | 큼 | 높음(CSS·JS 를 읽어야 함) | 중(실례가 적어 평가 비중은 낮게) |
| 숨김+난독화 조합 | 매우 낮음(1곳) | 큼 | 높음 | 상(부족) |

- 「높음·중간·낮음」은 이 표 안에서의 상대 순서다. 사이트 수 기준으로 60곳 이상 높음, 10~59곳 중간, 3~9곳 낮음, 1~2곳 매우 낮음으로 나눴다.

### 5-4. 많은 것은 줄이지 말고 무게로 다룬다

- 소프트 하이픈 238건을 지우면 실제 관측을 버리게 된다. 데이터는 그대로 두고 학습·평가에서 무게만 낮춘다(예: 소프트 하이픈만 쓴 건을 묶어 한 묶음 몫으로).
- 나눌 때(학습·검증·시험)는 사이트 단위로 나눈다. 같은 사이트가 학습과 시험에 함께 들어가면 틀을 외워서 점수가 오른다.

### 6-2. 생성 원칙: 부품은 전부 실측, 조립만 새로

출처 없는 문구를 지어내지 않는다. 생성 데이터 한 건은 아래 세 부품을 조립한 것이고, 부품마다 실제 출처를 적는다.

| 부품 | 가져오는 곳 |
|---|---|
| 광고 문구 | 이미 수집한 실제 광고 글(ETC·조합 1,002건) |
| 페이지 틀 | 실제 공공 사이트 게시판의 HTML 구조(DECOY 를 모은 정부·지자체 사이트 72곳의 게시판·공지·민원 페이지) |
| 숨김·회피 수법 | 실제로 관측한 코드(이 데이터의 숨김 방식, 사람 2·3 이 모은 숨김 CSS) |

- 생성분은 별도 파일에 두고 `is_synthetic: true` 와 부품별 출처를 적는다. **평가(시험)에는 실측만 쓴다.** 생성분은 학습과 지름길 점검용이다.
- 숨김 CSS 를 쓴 것은 렌더링으로 실제로 안 보이는지 확인한 것만 남긴다(실측과 같은 기준).

### 6-3. 공공사이트라는 주제에서 나온 아이디어

공격자는 공공 사이트의 어디를 노리는가를 먼저 정하고, 그 자리에 실제 광고를 넣는다.

1. **민원·자유게시판 스팸 이식.** 실제 그누보드 피해 글의 광고 문구와 숨김 방식을 지자체 「자유게시판」「칭찬합시다」 틀(전자정부 게시판 구조)로 옮긴다. 같은 문구를 두 틀에 넣은 짝을 만들면, 5-2 의 지름길 검사를 바로 할 수 있다.
2. **검색어 반사 페이지.** 공공기관 통합검색 결과 페이지는 검색어를 그대로 다시 보여 준다. 스패머가 이 주소에 광고 문구를 넣어 검색엔진에 색인시킨다(ETC 가운데 78건이 검색 결과 페이지 주소에서 나왔다). 실제 기관 검색 결과 틀에 실제 인코딩 광고 문구를 넣는다.
3. **방치된 하위 사이트·만료 도메인.** 오래된 행사 사이트나 만료된 기관 도메인을 업자가 사서 광고 사이트로 바꾼 사례를 실제로 봤다(한국어 마사지 광고 도메인이 인도네시아 슬롯 사이트로 바뀜). 공공 사이트 하단 「관련 사이트」 링크가 이런 도메인을 가리키는 경우를 링크 목적지 숨김 양성으로 만든다.
4. **메타 태그 숨김 확장.** 실제 메타 스팸 문구 21건을 다른 공공 사이트의 `<head>` 틀로 옮긴다. 메타 태그는 화면에는 안 보이고 검색 결과에만 나와서, 기관 이름 옆에 도박 문구가 뜨는 피해가 크다.
5. **css_content 변형.** 실례 1건(카드 위에 `::after { content: '...' }` 로 「안전한카지노」를 그림)의 방식을 공공 사이트 틀에 옮기고, 실제로 쓰이는 CSS 기법으로 변형한다. CSS 이스케이프(`\CE74` = 카)로 글자 감추기, `attr(data-*)` 로 속성값 끌어오기, 여러 의사요소에 글자 나눠 넣기. 변형마다 렌더링으로 글자가 실제로 보이는지 확인한다.
6. **Base64 목적지 숨김.** 실례 3건의 방식(버튼 `data-href` 에 Base64, `atob()` 으로 링크 만들기, 링크 표 Base64)을 공공 사이트 배너·바로가기 영역에 넣는다. 한국어 문구를 Base64 로 숨긴 것은 실례가 없으므로 「가능성 시험용」으로 따로 표시한다.
7. **숨김+난독화 조합.** 사람 2·3 의 실제 숨김 CSS(투명 글자·화면 밖 이동)에 이 데이터의 닮은꼴·자모 광고 문구를 넣는다. 유일한 실례(같은 색 숨김 속 「#ㅌㅌ사이트」)와 같은 구조다.

### 6-4. 정상 쪽(DECOY) 생성: 공공 사이트에 실제로 있는 「광고처럼 보이는 정상」

탐지기를 엄하게 만들수록 아래 정상 요소를 잘못 잡는다. 공공 사이트에서 흔한 것들이라 음성으로 만들어 둔다.

| 정상 요소 | 왜 헷갈리나 |
|---|---|
| 첨부파일 내려받기 주소·세션 값의 Base64 | Base64 탐지기가 걸린다 |
| 필수 입력 표시(`::before { content: '*' }`)·아이콘 글꼴의 CSS content | css_content 탐지기가 걸린다 |
| 긴 낱말 줄바꿈용 소프트 하이픈 | 보이지 않는 글자 탐지기가 걸린다 |
| 외부 링크 경고 페이지(`/redirect?url=...`) | 링크 목적지 숨김 탐지기가 걸린다 |
| 그누보드·카페24 로 만든 기관·협회 게시판의 정상 글 | 엔진 지름길을 끊는다(6-1 의 부족분) |
| 도박 중독 예방 안내·불법 대출 피해 신고 안내 | 광고어(도박·대출)가 정상 문맥에 나온다 |

> 처음 판: 이 가운데 실제 공공 사이트에서 바로 모을 수 있는 것(소프트 하이픈, 외부 링크 경고, 중독 예방 안내, 그누보드 기관 게시판)은 생성보다 수집을 먼저 한다.

- **10-13 수집으로 했다(생성 아님).** ETC 수법을 쓰는 정상 요소 100건이 폭 없는 문자 · 인코딩 · 링크 경유 주소 · 메타 · CSS content 각 20건이고, CSS content 는 아이콘 글꼴 문자 · `*`·`▼` 같은 기호 · 「메뉴」「검색」 라벨이고, 링크 경유 주소는 로그인 복귀 10 · 게시판 링크 이동기 7 · SNS 공유 3 이다. 그누보드·카페24 게시판에서 나온 정상 요소도 이 300건에 들어 있다. 남은 것: 소프트 하이픈은 1건뿐이다. 첨부파일 · 세션 값의 Base64 는 이번에 찾지 않았다.

### 6-5. 생성하지 않을 것

- 소프트 하이픈 쏠림은 생성으로 맞추지 않는다. 다른 글자를 일부러 많이 만들면 실제 관측 비율을 왜곡한다(5-4 의 무게 조정으로 다룬다).
- 출처를 댈 수 없는 광고 문구·업자 이름·연락처는 만들지 않는다.
